# Prompt — Criar PRD

Com base em toda a definição, pesquisa e validação já realizadas nesta conversa, crie o `docs/product/PRD.md` do produto.

O PRD deve se tornar autossuficiente como principal fonte de contexto funcional para as próximas etapas. Não dependa do histórico anterior para compreender o produto depois que o PRD estiver pronto.

Inclua somente o que for útil para construir o produto: problema, público, proposta de valor, core loop, escopo do MVP, requisitos/regras, não objetivos, métricas de sucesso, riscos e hipóteses ainda abertas.

Não escolha stack tecnológica nem faça System Design neste documento.

Ao final, revise se o PRD representa corretamente o produto e se contém contexto suficiente para um agente diferente produzir o System Design sem precisar ler esta conversa.
