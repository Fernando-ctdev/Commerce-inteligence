# Engineering Principles

Principles define **como implementamos neste projeto**.

Exemplos:

- linguagem canônica de domínio;
- boundaries e invariantes;
- preferência por código explícito;
- abstração apenas em fronteiras reais;
- anti-overengineering;
- política de testes;
- validação de entradas;
- isolamento/segurança;
- quando um novo ADR é obrigatório.

Principles deve permanecer mais estável que detalhes de stack.
